# Qwen 动作策略：训练规模与 AutoDL 预算规划

更新日期：2026-10-29。本文区分实测、预算假设和建议；训练数据量不能保证胜率改善。第一阶段总上限仍为 500 元，当前未开通云实例。

## 训练对象与独立对局

训练对象是 Qwen2.5-1.5B-Instruct 的注意力 LoRA 和 192 个动作 token 对应的词表行。原 MirrorForce 冠军模型冻结，作为示范教师、在线监督教师和固定对手，不参与参数更新。

独立对局的数据流是：游戏引擎 → 本方可见观察与合法动作 → 无损语义序列化及历史裁剪 → Qwen → 单个动作 token → 当前菜单索引 → 原生响应编码 → 游戏引擎。引擎负责规则与合法性，学生负责非强制动作的策略选择。当前不训练自然语言解释或思维链，不能把动作输出描述为已经验证的推理过程。

`--independent-student --selection greedy` 使用 StudentPolicy，学生端不调用教师评分；教师只控制对手。在线蒸馏使用 DistillPolicy，动作仍由学生选择，教师沿实际动作同步记忆并提供监督。单一合法动作可直接执行，异常不得由教师接管。

## 已知本机证据

- GPU：RTX 4060 Laptop，约 8GB 显存。
- 真实 Qwen 推理已测 3572、16333、16365 输入 token；forward 与标准 generate 选择一致，概率有限。该探针 PyTorch 峰值分配约 4.35GiB，不含教师进程。
- 真实两步 SFT 已完成，梯度累积为 1，每步输入 3865 token；它只验证链路，不代表策略已经学会打牌。
- 旧设置下真实恢复loss一致，但更新张量和固定输入log概率出现漂移；重复恢复也漂移且RNG状态相同。启用严格确定性算法后，微型CUDA/BF16和真实1.5B两步恢复复测均已通过：LoRA、动作行及固定输入动作log概率逐位一致，最大差异0。结论限于本次同设备/环境/样本，不能把相同loss当作恢复等价，也不保证跨设备逐位复现。
- 真实训练探针（独立GPU进程、教师已关闭）：3865-token输入，预热后SFT约2.81秒、KL约2.78秒/更新，约1380输入token/秒；PyTorch峰值分配5600890880字节、预留6840909824字节。每次一个决策，包含序列化、前向、反向、梯度裁剪和AdamW更新，不包含保存与加载；样本少且同状态重复，不是正式训练吞吐基准。
- 16379-token输入的首个SFT更新成功，但耗时249.89秒（约65.5输入token/秒），PyTorch峰值逻辑分配8801172480字节、预留9758048256字节；逻辑分配已经超过设备报告总显存8585216000字节，不能据此声称8GB有容量余量。实测呈明显性能下降，具体驱动分页/分配原因尚未定位。之后主动停止剩余长输入探针，未完成的第二次长SFT和长KL不计通过，也没有记录为OOM。
- 一批 267 条真实引擎轨迹的必要输入 P50/P95/max 为 7135/8298/8512；保留可容纳历史后多数接近 16384。正式预算按平均 12000～16000 输入 token/决策测算，比按纯盘面长度估算更保守。
- 上一次教师采集已完整落盘 16 局、3458 条非强制决策；WSL 重启后任务不再运行，原计划 20 局没有完成汇总。保留原始记录，不将缺失局视为成功。
- 真实独立学生对局已完成1对2局：137.1/121.8秒，0异常、0学生端教师评分查询，两局均负。记录动作45/31个，包含协议强制菜单；当前弱策略的短对局不能代表训练后模型的决策数量。若直接按这两局均值外推400局，约14.4小时，仅作为本机弱模型的粗略参考，不作为正式云端报价。

## 训练规模建议

先看学习曲线，再扩量。以下是试验起点，不是效果承诺：

| 层级 | SFT 独立决策 | SFT 数据遍历量 | 在线蒸馏 | 用途 |
|---|---:|---:|---|---|
| 工程冒烟 | 2～100 | 少量更新 | 少量整局和 KL 更新 | 验证恢复、资源、动作闭环 |
| 小规模学习试验 | 1000～2000 | 约 1 次，先比较持出 KL/动作一致率 | 3 轮，每轮约 500～1000 条，按整局入库 | 判断是否有学习信号 |
| 第一阶段正式候选 | 5000～10000 上限 | 先 1 次，验证集支持时再考虑第 2 次 | 3 轮，每轮最多 2000 条 | 完整三组对照与固定对局报告 |

以完整对局划分训练与验证，不把同局相邻状态拆到不同集合。同一盘面对动作顺序做置换不算新增独立对局。教师示范和在线状态应覆盖先后手、长短对局、不同决策类别；不能只堆同一组合的重复提示。

优先在 1000～2000 条试验中确认：SFT 损失正常、持出动作指标改善、真实对局异常率可接受。若训练指标下降而验证恶化，优先排查数据、动作映射和过拟合，不盲目增加 epoch。在线采样必须使用上一轮更新后的学生，三条对照分支匹配实际更新数与有效输入 token 数。

目前示例配置的 200 万 token 是运行上限，约为 125 条 16K 决策的单次处理量，不能称为已充分利用一万条数据。正式设置需要分开计算初始 SFT 与后续对照的预算，再核对实际样本覆盖记录。精确 token 组批可能重复抽取部分长度样本，处理量除以数据总 token 仅是等效遍历次数，不保证每条都访问。

## 选卡建议与环境

先试单张 RTX 4090 24GB，BF16 LoRA rank 16、microbatch 1、梯度检查点、梯度累积；不做 1.5B 全参数训练。24GB 是根据模型大小和本机结果提出的首选容量，16K 训练能否稳定运行及速度须云端实测。本机8GB保留用于短输入冒烟与接入验证，避免照搬16K长训练；也不能用本机65.5 token/秒简单按算力比例预测4090，后者可能跨过容量限制。训练时关闭教师和采样进程，采样时才同时加载教师与学生。

云实例建议至少 32GB 系统内存，优先 64GB；环境试跑准备约 50～100GB 可用磁盘，正式训练按保留检查点数量重新核算。当前优化器检查点约 1GB/份，不能无上限保存。例如 SFT 5000 次加9个各2000次的分支阶段，共23000次更新，默认每50次保存会产生约460份检查点，磁盘远超100GB。单独训练CLI可调 `--save-every`；每1000次保存约23份，但中断损失窗口也更大。当前编排器尚未暴露保存频率和保留数量配置，正式大规模运行前需补充该配置或采用审计过的分阶段CLI，不能直接照搬默认值开跑。保留最终权重、必要恢复点与最佳验证检查点后再决定存储配额，不在训练过程中随意删除仍被后续阶段引用的文件。

5090 32GB 可作为后续选项，但现有本机 torch2.5.1/cu124 组合不能直接当作其兼容性证明，应先选择支持其架构的新运行环境，分别验证 PyTorch、JAX 教师和原生引擎。A800 80GB 暂不作为 1.5B LoRA 首选；只有 24GB 实测容量不足或更大 batch 的每元吞吐更好时再比较。

2026-10-29 检索 AutoDL 官网公开首页的索引展示：4090 24GB 为 1.88 元/小时，5090 32GB 为 2.78 元/小时，A800 80GB 为 5.59 元/小时。首页动态加载，公开索引不能代替实例报价；官方计费文档也要求以网站现价为准。规划时先按 4090 每小时 2～3 元做敏感性分析，租用前填写实际价格。

来源：[AutoDL 官网](https://autodl.com/home)、[AutoDL 计费文档](https://www.autodl.com/docs/price/)。实例按开关机时长计费，即使没有运行 GPU 任务仍计费；扩容数据盘另计。结束 Python 进程不等于实例关机。

## 成本公式和敏感性分析

设 SFT 实际输入处理量为 S，三条对照分支各自累计输入量为 D，训练有效吞吐为 R 输入 token/秒，在线学生非强制决策数为 N，每决策端到端平均耗时为 t 秒：

训练小时 = (S + 3D) / R / 3600。

采样或评测小时 ≈ N × t / 3600 + 引擎、对手、预处理、强制动作及加载耗时；以整局墙钟计费为最终依据。不能按单个输出 token 的生成速度计算。

例：SFT 5000 条 × 12000 token × 1 次 = 6000 万；每个分支后续 3 轮 × 2000 条 × 12000 token × 1 次 = 7200 万；三组加 SFT 共 2.76 亿输入 token。以下仅是假设吞吐，不是 4090 实测：

| 实测训练吞吐 R | 纯训练小时 | 按 2 元/小时 | 按 3 元/小时 |
|---:|---:|---:|---:|
| 500 token/秒 | 153.3 | 306.7 元 | 460 元 |
| 1000 token/秒 | 76.7 | 153.3 元 | 230 元 |
| 2000 token/秒 | 38.3 | 76.7 元 | 115 元 |

这张表不含采样、评测、空闲、存储、重跑。若平均输入为 16000，表中时间和训练费用再乘 4/3。若增加 SFT 第 2 次遍历，还需另加对应输入量。

正式评测若包含初始 SFT 加三条后续分支，共 400 局。假设每局平均 200 条非强制学生决策，则共 8 万条；每决策端到端 1/2/5 秒时，仅学生决策部分分别约 22.2/44.4/111.1 小时。这也是必须先实测真实学生整局速度的原因，教师对局速度不能代替学生评测速度。

## 500 元内的执行门槛

沿用分配：环境与性能测量 50 元，采样与训练 250 元，评估与重跑 150 元，存储及余量 50 元。

1. 先按量租 4090 做 1～2 小时测量，不先买长租。测短/长输入 forward、SFT/KL 更新的稳定峰值显存、有效吞吐，以及完整学生对局平均/P95 墙钟。
2. 以测量结果代入公式，同时预留全部评测费用。拟执行训练费用超过 250 元，或评测超过 150 元，则缩小数据处理量并同步缩小三组训练预算；不只缩小某一分支。
3. 数据量缩小仍保留完整三组和预定正式评测，若连评测预算都无法满足则停止扩展，报告预算约束，不声称完成原定正式实验。
4. 停止扩展阈值按已花费用加剩余必要费用判断，不能等余额耗尽再检查。

因此，500 元有机会完成一个可信的小规模对照项目，但是否足够支持一万条数据、多遍训练和完整评测，需要云端实测后决定；当前不承诺一套固定数据量一定得到较好胜率。
