# 本机与 MirrorForce 对战

本机部署已完成并经过实际验证：GPU 推理、两局完整模型对战，以及 MDPro3 中的玩家响应与 AI 连续出牌均正常。详细证据见同目录的《本机人机对战部署进度》。

## 启动

1. 打开 `F:\Game\MDPro3\MDPro3.exe`。
2. 进入“联机模式 → 本地主机”，使用单局模式、8000 基本分、5 张初始手牌、每回合抽 1 张，特殊选项选择“不检查卡组”，保持洗切卡组。
3. 点击“创建主机”，在房间左下角选择 `MirrorForce-SkyStriker` 卡组。
4. 双击 `F:\YGOagent\local-tools\Start-MirrorForce.cmd`。它加载发布模型并加入本机 7911 端口的房间。首次 GPU 编译预热实测约 5 分钟；编译缓存会保留，但新形状或环境变化仍可能触发编译。应等控制台显示服务就绪、房间出现 MirrorForce 后再开始。
5. 在 MDPro3 中点击“准备”和“开始”，按界面进行猜拳与先后手选择，然后正常操作卡片。

目前按发布模型的训练范围使用闪刀姬镜像卡组。模型使用原始 `iterate` 权重和 greedy 动作选择；没有接入搜索，也不进行训练或参数更新。

MirrorForce 由上述外部入口加入房间；房间里的“添加 AI”按钮管理的是客户端内置机器人。

## 再开一局与退出

一局结束后重新创建本地主机房间，再次运行同一个启动入口。启动管理器会检查服务身份，优先复用仍在运行的同一模型服务。

退出当前测试时，可以正常结束或退出房间，再关闭 AI 控制台。关闭连接会清理该对局的会话；Linux 环境空闲后可能自动停止，之后再运行入口会重新启动环境。

## 常见情况

- CMD 提示 `'p'` 或 `'ershell.exe'` 不是命令：启动批处理已修正为纯 ASCII 文件名与 CRLF 换行；关闭旧窗口后重新运行原入口。可执行 `Start-MirrorForce.cmd -CheckOnly` 检查 CMD 到 PowerShell 的启动链路，该模式不启动模型或连接房间。
- 连接被拒绝：先确认 MDPro3 已创建本地主机房间，端口为 7911。
- 长时间加载：查看控制台提示的模型服务日志；首次 GPU 编译可能需要数分钟，不要反复启动。
- 卡组不能准备：确认选择配套卡组，并使用“不检查卡组”的测试设置。
- 运行报错：保留控制台内容与对应日志；启动入口会报告失败，不会自动切换到随机策略。
