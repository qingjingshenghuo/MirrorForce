## 盘面入口

从mirrorforce目录运行：

```bash
python -m mirrorforce.distill.benchmark --data /path/validation/samples.jsonl \
  --out /path/frozen-validation.jsonl --split validation --limit 200 \
  --seed 42 --per-game 20 --per-turn 3
python -m mirrorforce.distill.audit --data /path/frozen-validation.jsonl \
  --adapter /path/checkpoint --out /path/audit.json
```

benchmark输出固定JSONL和manifest，记录来源摘要及索引；不覆盖已有文件。audit记录逐样本KL和动作一致率、菜单重排一致率、对局分组置信区间。需核对冻结数据的来源完整对局没有进入训练。

## WinBot入口与来源

本机下载IceYGO/windbot提交 `dec0535f8669dca01457a898890a968139711b19`，使用SkyStriker执行器和本项目固定卡组。当前没有取得MirrorForce作者当时的精确WinBot构建，不能声称与原曲线数值直接可比。

源码保存在忽略目录local-resources/windbot-source。WSL安装mono-devel后以Release、Any CPU构建。两处列表元组交换改为等价临时变量，以兼容Mono编译器；Program增加可选WINDBOT_SEED初始化随机数，不改闪刀姬执行器。补丁保存在local-tools/windbot-mono-seed.patch。源码及第三方许可证仍归原作者。

arena入口需要rules资源身份文件、学生adapter、卡组、数据库、脚本根、原生模块和windbot-exe。它直接使用客户端观察器和独立学生，不加载教师网络。仅向WinBot转发本方收到的消息，以CTOS响应驱动原生引擎。manifest记录可执行文件及依赖摘要、规则身份、模型摘要、种子和选择方式；不同对手身份的评测拒绝直接比较。

```bash
python -m mirrorforce.distill.arena --rules /path/rules-manifest.json \
  --adapter /path/checkpoint --deck /path/SkyStriker.ydk --cards-db /path/cards.cdb \
  --script-root /path/assets --native /path/duel_native.so \
  --windbot-exe /path/WindBot.exe --out /path/new-evaluation --seed 200100 --pairs 1
```

运行前导出MF_DUEL_NATIVE和MF_EFFECTINFO_LIB，使用配置好的GPU学生环境。规则身份必须与数据库和原生模块一致。分数包括正常胜平负，异常单列；投降、协议错误、客户端状态不一致不当作正常策略获胜。

## 迭代规则

每轮先检查训练数据覆盖、标签映射、损失、显存和运行异常，再用固定WinBot开发发牌比较。没有涨点时保留失败轮次，分析动作和对局问题，再预先说明下一轮改动。不能通过换开发种子、过滤输局、缩短失败局或教师接管制造提升。候选改动在独立开发确认集复核，最终测试只在方案冻结后运行。
